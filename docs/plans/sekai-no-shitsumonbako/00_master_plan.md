## 2. 【重要】取材方法の修正点 — 自動収集は禁止

ご指示の著作権ガードは正しいのですが、**それとは別レイヤーのリスク**が1つあります。

### リスクの中身

- Reddit社は**投稿データを有償ライセンス事業として販売**しています（2024年にGoogle社・OpenAI社との契約を公表）。
- したがって**無断の機械的収集（スクレイピング・API大量取得・DB保存）は、著作権以前に「利用規約違反」＋「Reddit社のビジネスを侵害する行為」**として扱われます。
- 実際にReddit社は2025年6月、無断収集を理由にAI企業（Anthropic社）を提訴しています。
- ナスダック上場企業として、**「訴えられる可能性のある取材手法」は、勝てるかどうかに関係なく採ってはいけません**。開示・レピュテーションのコストが利益を上回ります。

### 修正後の取材ルール（これを厳守）

| ✅ やってよい | ❌ 絶対にやらない |
|---|---|
| 編集部員が**人の目でブラウザを読む**（＝一般利用者としての閲覧） | 自動巡回ツール・スクレイパーの使用 |
| 読んで得た**傾向・論点を自分のメモに日本語で要約**する | 投稿本文のコピー＆保存（社内メモも含む） |
| 3件以上に共通する疑問を**編集部の言葉で書き直す** | API経由での大量取得・社内DBへの蓄積 |
| 「海外のコミュニティで議論されている」と書く | 「Redditで話題」「r/○○では」と書く |

> **なぜこれで安全か**：著作権法が守るのは「表現」であって「アイデア・事実・傾向」ではありません。
> 「多くの人が◯◯を疑問に思っている」という**傾向は誰の著作物でもない**ので、
> それを編集部の言葉で書き起こし、編集部が自力で回答を書く限り、著作権上の問題は生じません。
> 詳細は `02_legal_guard.md`。

### 追加ルール：3ソース原則

**同じ疑問が、独立した3件以上の場所で確認できたものだけを採用**する。

- 理由：1件の投稿にしか出てこない質問は「その人の体験・創作的表現」に寄ってしまい、一般化ではなく実質的な翻案になるリスクがある。
- 副次効果：3件以上出る質問＝本当に需要のある質問。**リスク回避と品質向上が同時に達成できる。**

## 3. 企画の目的と仮説

### 目的

1. **GEO（Generative Engine Optimization）**：AI検索エンジンに引用されるコンテンツ資産を作る。
2. **検索流入の裾野拡大**：ロングテールの疑問文クエリを面で押さえる。
3. **第2フェーズの助走**：将来VV自前のコミュニティ（会員からの質問）に質問源を切り替える前提の練習台。

### 検証したい仮説

> **仮説**：Q&A形式の記事は、通常記事に比べてAI検索での引用率が高い。

- Q&A形式が有利と考えられる理由：
  - 1ページ＝1つの疑問に完結して答えるため、AIが「この質問への答えはここ」と紐づけやすい。
  - 冒頭に結論があるため、AIが要約せずそのまま引用できる。
  - ユーザーの検索語（自然文の質問）と見出しが一致しやすい。
- **これは仮説であって確定事実ではない**。だから第1フェーズはKPI検証が主目的。
- 検証結果しだいで「増やす／形を変える／たたむ」を判断する（判断基準は `04_kpi_measurement.md`）。

## 4. 記事の基本形

タイトル：`Q. ＜質問文＞｜世界の質問箱 #n`

| 構成 | 内容 | 目安 |
|---|---|---|
| ① 質問提示 | 世界で議論されている文脈を1〜2文 | 80〜120字 |
| ② 結論ファースト回答 | 最初の1文で答えを言い切る | 40〜80字 |
| ③ 理由・背景 | 出典付きで根拠を説明 | 600〜1,200字 |
| ④ VVの考え方に接続 | **該当時のみ**。毎回入れない | 150〜300字 |
| ⑤ 注記 | 健康・医療系は非診断注記を必須 | 定型文 |

タグ：`世界の質問箱` ＋ カテゴリータグ（棚に応じる）

詳細と技術要件は `05_article_template.md`。

## 6. 体制・ペース・工数

### 体制

| 役割 | 担当 | 責任 |
|---|---|---|
| 質問発掘（観察） | 編集部員1名 | 週1回まとめて観察、質問候補を10案ストック |
| 質問文の起草 | 編集部 | 一般化・リライト。3ソース原則の確認記録を残す |
| 回答執筆 | 編集部 | 完全オリジナル。出典の一次情報確認 |
| 法務チェック | 法務（薬機法・景表法） | 健康／スキンケア棚は**全件必須**、他棚は抜き取り |
| 公開・技術実装 | CODE | 棚判定・URL・構造化データ・タグ |
| 効果測定 | 情報戦略室 | 月次でKPIレポート |

### ペース

- **週2〜3本**でスタート（既存の毎日更新枠とは別建て）。
- 第1フェーズ＝**8週間 / 16〜24本**を1つの評価単位とする。
- 記事1本あたり工数目安：観察＋起草0.5h／執筆2.0h／法務0.5h／公開0.5h＝**約3.5h**。
  → 週3本で約10.5h/週。**専任1名を置かず、既存編集リソースの2〜3割で回せる規模**。

### やらないこと（スコープ外）

- 速報性のあるニュース記事化 → 別枠でやること。この連載は**時間が経っても価値が落ちない疑問**だけを扱う。
- 記事の量産（週5本以上への性急な拡大） → KPIが出るまで増やさない。

## 7. 第2フェーズへの布石（今すぐ着手すべき1件）

**VV会員規約に、投稿コンテンツの利用許諾条項（UGCライセンス条項）を今のうちに入れておくこと。**

- 理由：第2フェーズで「会員から寄せられた質問」を記事化する際、**規約に利用許諾がないと、今Redditに対して回避しているのと同じ問題を自社会員に対して起こす**。
- 必要な条項の骨子：
  1. 会員が投稿した内容について、VVが**無償・非独占・地域無制限・再許諾可**の利用権を得る旨
  2. 記事化・編集・翻訳・二次利用を含む旨
  3. 個人が特定されない形に加工して利用する旨
  4. 投稿者は第三者の権利を侵害しない内容を投稿する旨（表明保証）
- **担当：法務。第1フェーズ終了（8週後）までに規約改定を完了させる。**
- これを先にやっておけば、第2フェーズは法務論点ゼロで走り出せます。
