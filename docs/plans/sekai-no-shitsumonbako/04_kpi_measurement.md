# KPI計測設計

**目的**：Q&A記事と通常記事で、AI検索からの引用率に差が出るかを検証する。

---

## 0. 【前提条件】これをやらないと計測できない

**Q&A記事のURLに、通常記事と区別できる文字列を入れること。**

```
推奨： https://（VVドメイン）/questions/＜スラッグ＞
```

- 理由：Google Search Console も Bing ウェブマスターツールも、**URLに含まれる文字列でフィルタして集計する**のが最も確実な分離方法。
- タグだけで分けると、管理画面上で「Q&A記事だけの数字」を切り出せず、**比較が事実上できなくなる**。
- **CODEへの依頼事項：連載開始前にURL設計を確定すること。後からURLを変えるとリダイレクト対応が発生し、計測も分断される。**

---

## 1. 比較設計（フェアな比較にするための条件）

「Q&A記事のほうが引用されやすい」を検証するには、**条件を揃える**必要がある。

| 条件 | 揃え方 |
|---|---|
| 本数 | Q&A記事 16〜24本 に対し、**同じ棚の通常記事から同数を対照群として選定** |
| 期間 | 公開から**28日間**の数字で比較（新記事はインデックス直後の数字が不安定なため） |
| 棚 | 棚ごとに比較する（fashion同士、health同士）。棚をまたいで合算しない |
| テーマ難度 | 極端に競合の強いビッグワード記事は対照群から外す |

> **注意**：対照群を後から都合よく選ぶと結論が歪む。**対照群は連載開始時点で先に決めて記録しておくこと。**

---

## 2. 測定指標

### 主指標（AI検索での引用）

| 指標 | 取得元 | 備考 |
|---|---|---|
| AI検索経由の表示数・クリック数 | Bing ウェブマスターツール（AIパフォーマンス関連レポート） | Copilot等での露出を確認する |
| AIクローラーのアクセス回数 | **サーバーログ / CDNログ** | 下記2-1 |

### 副指標（従来検索）

| 指標 | 取得元 |
|---|---|
| 表示回数 / クリック数 / CTR / 平均掲載順位 | Google Search Console（URLフィルタ `/questions/`） |
| 同上 | Bing ウェブマスターツール |

### 事業指標（参考）

| 指標 | 取得元 |
|---|---|
| 記事到達後の回遊率・滞在時間 | GA4 |
| 記事経由のCV | GA4（ただし本連載の主目的ではない。過度に重視しない） |

### 2-1. サーバーログによる補助計測（推奨）

管理画面のレポートだけに依存せず、**自社ログでAIクローラーの訪問を直接数える**。

- ログの `User-Agent` から、AI検索・AIアシスタント系のクローラーによるアクセスを抽出し、URLごとに集計する。
- 集計単位：`/questions/` 配下 vs それ以外。
- 利点：**プラットフォーム側のレポート仕様変更に左右されない、自社で握れる指標**になる。
- **担当：情報戦略室。連載開始と同時にログ集計を仕込むこと。**

---

## 3. 【正直な但し書き】不確実な点

- **Bing ウェブマスターツールのAIパフォーマンス機能が、Copilotでの「引用」をどの粒度で出すかは未確認**です。表示・クリックは取れても、「AIの回答文中で引用された回数」そのものが取れるとは限りません。
  → **担当者が実際の管理画面で仕様を確認し、本ドキュメントを更新すること。**
- **AI検索側の指標は各社とも仕様変更が頻繁**です。単月の増減で一喜一憂せず、**トレンドで見る**こと。
- 上記の理由から、**サーバーログでの補助計測（2-1）を必ず併用**してください。管理画面が使えなくなっても計測が止まりません。

---

## 4. レポート様式（月次）

```
■ 世界の質問箱 KPIレポート（YYYY年M月）

1. 公開本数：n本（累計 N本）
2. Q&A記事 vs 対照群（棚別）
   ┌────────┬──────────┬──────────┬───────┐
   │ 棚      │ Q&A記事   │ 通常記事  │ 倍率  │
   ├────────┼──────────┼──────────┼───────┤
   │ fashion │ 表示 x    │ 表示 y    │ x/y   │
   │ health  │ ...       │ ...       │ ...   │
   │ trend   │ ...       │ ...       │ ...   │
   └────────┴──────────┴──────────┴───────┘
3. AIクローラー訪問回数（自社ログ）：Q&A n回 / 通常 m回
4. 勝ちテーマ・負けテーマ（各3件）
5. 次月の打ち手（1〜3行）
```

---

## 5. 判定基準（8週後の意思決定）

| 判定 | 条件（AI引用率／対照群比） | アクション |
|---|---|---|
| **拡大** | 1.5倍以上 | 週5本へ。専任配置。第2フェーズ前倒し |
| **継続** | 1.0〜1.5倍 | 週2〜3本維持。タイトル・構成を改善 |
| **見直し** | 0.8〜1.0倍 | 勝ち棚・勝ちテーマに集中 |
| **停止** | 0.8倍未満かつ改善見込みなし | 連載終了。学びをGEO標準テンプレに還元 |

> 数字が出なかった場合も**失敗ではない**。「Q&A形式は当社ドメインでは効かない」という**再現性のある知見**が残り、他施策の無駄打ちを防げる。判定は感情ではなく数字で行うこと。
