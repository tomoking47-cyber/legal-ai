# 記事テンプレート＋GEO技術要件

---

## 1. 記事テンプレート

```markdown
# Q. ＜質問文＞｜世界の質問箱 #n

＜①冒頭：世界で議論されている文脈を1〜2文＞
例）「海外のコミュニティでも、この疑問は繰り返し話題になります。」

## A. ＜結論を1文で言い切る（40〜80字）＞

＜結論の補足を2〜3文＞

## なぜそうなのか

＜②理由・背景。出典付きで600〜1,200字＞
＜見出し（h3）を2〜3本立てて、AIが部分引用しやすい構造にする＞

## VVの考え方

＜④該当時のみ。3本に1本以下。150〜300字＞

---

### 出典
- 機関名『資料名』（公表年）URL
- 機関名『資料名』（公表年）URL

### ご注意
＜⑤注記。健康・医療系は下記の定型文を必須で入れる＞
```

### 非診断注記（定型文・健康/医療系は必須）

> 本記事は一般的な情報の紹介であり、特定の症状の診断・治療・予防を目的としたものではありません。
> 体調や肌の状態に不安がある場合は、自己判断せず医療機関にご相談ください。
> 効果や感じ方には個人差があります。

### スキンケア注記（定型文・スキンケア系は必須）

> 本記事で紹介する内容は、化粧品の一般的な使い方に関する情報です。
> 化粧品は疾病の治療・予防を目的とするものではありません。
> 肌に異常を感じた際は使用を中止し、皮膚科専門医にご相談ください。

---

## 2. タイトルの作り方（AI検索で拾われるために）

| ルール | 理由 |
|---|---|
| **1記事＝1つの疑問**。複数を詰め込まない | AIが「この質問への答えはここ」と紐づけやすくなる |
| 質問文は**読者が実際に打ちそうな自然文**にする | AI検索は自然文クエリが中心 |
| 質問文は**40字以内** | 表示切れを避ける |
| `#n` は連載の通し番号。**タイトル末尾に固定** | シリーズとして認識させる |

例：
- ✅ `Q. 化粧水は重ね付けしたほうがいいの？｜世界の質問箱 #1`
- ❌ `Q. 化粧水と乳液の順番や重ね付け、朝と夜の違いは？｜世界の質問箱 #1`（疑問が3つ入っている）

## 3. GEO技術要件（CODE実装事項）

| # | 要件 | 目的 |
|---|---|---|
| 1 | URLに `/questions/` を含める | **KPI計測の前提**（`04_kpi_measurement.md`） |
| 2 | 質問文を `h1` に置く | ページの主題を明示 |
| 3 | `h1` の**直後**に結論（40〜80字）を平文で置く | AIがそのまま引用できる位置に答えを置く |
| 4 | 構造化データ `FAQPage` を実装 | 機械可読な形で「質問と答え」を明示する |
| 5 | 公開日 `datePublished` と更新日 `dateModified` を明示 | 情報の鮮度をAI・検索に伝える |
| 6 | 出典は**外部リンク**として実装（テキストだけにしない） | 根拠の追跡可能性を示す |
| 7 | 連載インデックスページを作り、全記事から相互リンク | シリーズとしての一体性 |
| 8 | 棚タグ＋`世界の質問箱`タグを付与 | サイト内回遊とカテゴリ理解 |
| 9 | `robots.txt` でAI検索クローラーをブロックしていないことを確認 | **ブロックしていたら引用されようがない。最優先で確認** |

### 構造化データの実装例（FAQPage）

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [{
    "@type": "Question",
    "name": "化粧水は重ね付けしたほうがいいの？",
    "acceptedAnswer": {
      "@type": "Answer",
      "text": "＜結論の1〜2文をそのまま入れる＞"
    }
  }]
}
```

> **正直な但し書き**：Googleは2023年8月にFAQのリッチリザルト表示を大幅に縮小しており、
> **この構造化データを入れても検索結果の見た目が変わることは基本的に期待できません。**
> それでも実装する理由は、**「質問」と「答え」の対応関係を機械可読な形で明示できる**ためです。
> 見た目のリッチリザルト目当てではない、という点を編集部・CODEの共通認識にしてください。

## 4. 執筆トーン

- **誠実に。わからないことは「わからない」と書く。**
- 断定できないものを断定しない。「〜という報告があります」「確立した結論は出ていません」を使う。
- 専門用語を使ったら、直後に「つまり〜」と噛み砕く。
- 読者を見下さない。「意外と知られていませんが」のような上から目線を避ける。
- **商品を売るためではなく、疑問に答えるために書く。** 結果として信頼が売上になる。
