# 『世界のいいニュース』企画設計書

- 起案：会長CEO指示（2026-09-08）
- 連載名（案）：**世界のいいニュース** ／ 英語表記：`Good News from the World`
- 位置づけ：『世界の質問箱』と**同じ設計思想・同じ法務ガード・同じ計測基盤**で走る姉妹連載
- ステータス：**GO（推奨）**

---

## 1. 結論

**やるべきです。しかも、これは『世界の質問箱』より事業インパクトが大きい可能性があります。**

理由：

1. **ブランドと完全に一致している。** VALUE VILLAGE＝価値ある村。「温かい・笑顔・幸せ」は後付けのテーマではなく、社名そのものの意味。**他社が真似しても薄っぺらくなるが、当社がやると必然性がある。**
2. **世界的に確立した潮流に乗っている。** 建設的ジャーナリズム（constructive journalism）／解決志向報道（solutions journalism）という領域が既に確立しており、英国 Positive News、米国 Good News Network 等の先行例がある。**当社が最初の実験台ではない、というのは経営判断上重要**です。
3. **既存メディアの構造的な空白を突いている。** 通常のニュースが悪い話に偏るのは、報道機関の悪意ではなく、クリック競争の構造的な帰結です。**構造的な偏りは、構造的な差別化の余地**でもあります。
4. **回遊とリピートに効く。** 悪いニュースは読んだあと離脱します。良いニュースは滞在し、共有されます。**シェア率とリピート率で差が出るはず**です（要検証）。

## 2. 【最重要】この企画のリスクは著作権ではなく「事実誤認」

正直にお伝えします。**この企画の最大のリスクは、法務リスクではありません。**

> **感動的だが、事実ではない話を掴んで発信してしまうこと。**

「いい話」は拡散されやすく、その過程で**盛られ、変形し、出所が消えます。** 泣ける話ほど、裏が取れないことが多い。
上場企業のメディアが誤情報を発信し、後から訂正する。これは**通常のニュースで誤報を出すより、ブランドへのダメージが大きい**。
「温かいメディア」を名乗っている以上、「調べていないメディア」と見なされた瞬間に価値がゼロになるからです。

### 対策：二次情報からは絶対に書かない

| ステップ | 内容 |
|---|---|
| 1 | SNS・まとめサイトで話題を**知る**（ここまでは自由） |
| 2 | **一次情報に到達できるか確認する** |
| 3 | 一次情報が**確認できなければ、どれだけ良い話でも書かない** |

**一次情報として認めるもの：**

- 公的機関の発表（省庁・自治体・大使館・国連機関等）
- 大学・研究機関の公式プレスリリース
- 企業・団体の公式プレスリリース、公式サイト
- 当事者本人の公式アカウント・公式発表
- 一次情報に基づく信頼できる報道機関の記事（**ただし記事本文は使わず、事実の確認にのみ用いる**）

**一次情報として認めないもの：**

- SNSの又聞き投稿、まとめサイト、匿名掲示板
- 出典が明記されていない「感動話」
- 発生時期・場所・当事者が特定できない話

## 3. 著作権ガード（『世界の質問箱』と共通）

| 項目 | ルール |
|---|---|
| 報道記事の本文 | **使わない。** リライトも翻案リスクがあるため不可 |
| 報道記事から得た**事実** | 使ってよい（事実は著作物ではない）。ただし**一次情報で裏を取る** |
| プレスリリースの本文 | **そのまま転載しない。** 事実を取り、VVの言葉で書く |
| **写真・動画** | **ここが最大の事故ポイント。** 下記3-1参照 |
| 当事者のSNS投稿文 | 引用・翻訳転載しない。事実のみ使う |
| 埋め込み（公式SNSの埋め込み機能） | **法務確認のうえ、公式の埋め込み機能を使う場合のみ可**。スクショは不可 |

> 参考：著作権法10条2項は「事実の伝達にすぎない雑報及び時事の報道」を著作物から除いていますが、
> これは人事・死亡記事のような**ごく短い事実の伝達**を想定した規定です。
> **記者が構成した報道記事の本文は通常は著作物**であり、この規定では守られません。詳細は `12_faq_copyright.md` Q7。

### 3-1. 画像の取り扱い（事故が起きるとしたらここ）

**他社サイト・SNSから画像を持ってくることは、いかなる理由でも禁止。**

使ってよい画像は以下のみ：

1. VVが撮影・作成した画像
2. 当事者・団体から**書面で利用許諾を得た**提供画像（許諾記録を残す）
3. 契約済みのストックフォト（ライセンス範囲を確認）
4. 政府標準利用規約等で二次利用が明示的に認められている公的機関の画像（出典明記）
5. VVが作成したイラスト・図版

**「出典を書けば使える」は誤りです。** 出典明記は引用の要件の1つにすぎず、それだけで転載が適法になるわけではありません。

## 4. 編集方針 — 「いいニュース」の定義

「いい話ならなんでもいい」にすると、企画が崩れます。**定義を先に決めます。**

### 採用する5つの型

| 型 | 内容 | 例（イメージ） |
|---|---|---|
| **A. 解決** | 課題が実際に解決された話 | ある地域の取り組みで、長年の問題が改善した |
| **B. 前進** | 研究・技術・制度が一歩進んだ話 | 治療法・環境技術・アクセシビリティの進展 |
| **C. 人の温かさ** | 見知らぬ人同士の善意が形になった話 | 地域の助け合い、返却された落とし物 |
| **D. 再会・達成** | 長い時間を経て報われた話 | 何年ぶりかの再会、遅れて叶った夢 |
| **E. 笑える** | 悪意のない、誰も傷つけない可笑しさ | 動物の行動、微笑ましいすれ違い |

### 採用しない（重要）

| ❌ | 理由 |
|---|---|
| **誰かの不幸を前提にした「感動話」** | 「不幸な人が救われた」構図で当事者を消費しない |
| **闘病・障害・災害を「感動の素材」にする** | 当事者の尊厳を損なう。扱う場合は当事者の意思を中心に据える |
| **他人を貶めることで生まれる笑い** | VVのブランドと不一致 |
| **実在個人の私生活の暴露** | プライバシー・肖像権 |
| **政治的・宗教的対立を含む話** | 「いいニュース」の受け取り方が読者によって割れる |
| **未成年が特定される話** | 本人・保護者の許諾がない限り扱わない |
| **裏が取れない「泣ける話」** | 上記2章のとおり最大リスク |

### トーン

- **煽らない。** 「涙腺崩壊」「衝撃」といった扇情的な見出しは使わない。
- **説教しない。** 「私たちも見習うべき」と読者に教訓を垂れない。事実を丁寧に伝え、感じ方は読者に委ねる。
- **当事者を主語にする。** 「感動をもらった」ではなく「その人が何をしたか」を書く。

## 5. 記事テンプレート

```markdown
# ＜見出し：何が起きたかを事実で＞｜世界のいいニュース #n

## ＜リード：40〜80字。何が起きたかを1文で＞

## 何があったのか
＜事実を時系列で。300〜600字＞

## なぜそれが起きたのか / その後どうなったか
＜背景と現在。出典付き。300〜600字＞

## VVはこう受け取りました
＜編集部の受け止め。2〜4文。説教しない。該当時のみ＞

---
### 出典
- 機関名・団体名『発表資料名』（公表年月日）URL
- 機関名・団体名『発表資料名』（公表年月日）URL
```

**タイトルのルール：**
- 事実を書く。煽らない。
- 40字以内。
- `#n` はタイトル末尾に固定。

## 6. 『世界の質問箱』との連動

**両連載は「VVの GEO 二本柱」として、同じ基盤に載せます。**

| 項目 | 世界の質問箱 | 世界のいいニュース |
|---|---|---|
| URL | `/questions/` | `/goodnews/` |
| 構造 | 結論ファースト | リードファースト（同じ思想） |
| 法務ガード | `02_legal_guard.md` | **同じものを適用**＋画像ルール強化 |
| チェックリスト | `03_editorial_workflow.md` | **共通版を使用** |
| 計測 | `04_kpi_measurement.md` | **同じ基盤で対照比較** |
| 棚 | fashion / health / trend | **横断（専用棚 or trend）※CODE判断** |

**相互リンク設計：**
- いいニュース記事の末尾から、関連する質問箱記事へ1本リンク。
- 質問箱記事の末尾から、関連するいいニュース記事へ1本リンク。
- 目的：回遊率の向上と、AIに対する「このサイトはこの領域の情報源だ」というシグナル強化。

## 7. ペースとKPI

### ペース

- **週2〜3本**でスタート（質問箱と合わせて週4〜6本）。
- 第1フェーズ＝**8週間 / 16〜24本**。
- 工数目安：発掘0.5h／裏取り1.0h／執筆1.5h／チェック0.5h／公開0.5h＝**約4.0h/本**
  → **裏取りに一番時間をかける**設計。ここを削ると企画が死にます。

### KPI（質問箱と共通基盤＋この企画固有の指標）

| 指標 | 見るもの |
|---|---|
| AI検索での引用（Bing AIパフォーマンス／自社ログ） | 質問箱と同基準で比較 |
| 表示回数・CTR（Search Console） | `/goodnews/` でフィルタ |
| **シェア率** | **この企画固有の主指標。** 良いニュースは共有される仮説の検証 |
| **回遊率・滞在時間** | 悪いニュースとの差が出るはずの指標 |
| **リピート率** | 「またこのサイトに来る」動機になっているか |

> **注意**：CVを主指標にしない。この連載はブランドと回遊のための投資です。
> 売上で評価すると、必ず煽り見出しに流れて企画が壊れます。

### 判定（8週後）

| 判定 | 条件 | アクション |
|---|---|---|
| 拡大 | シェア率が通常記事の2倍以上、または AI引用率1.5倍以上 | 週5本へ。専用棚を新設 |
| 継続 | 通常記事と同等以上 | 週2〜3本維持 |
| 見直し | 通常記事を下回る | 型（A〜E）を絞って再挑戦 |
| 停止 | 改善見込みなし | 学びを質問箱に還元 |

## 8. 公開前チェックリスト（この企画固有分）

`03_editorial_workflow.md` の共通チェックリストに**加えて**、以下を全項目確認：

- [ ] **一次情報に到達した**（機関名・発表日・URLを控えた）
- [ ] 出典URLを実際に開き、記載内容と一致することを確認した
- [ ] 発生**時期・場所・当事者**が特定できている
- [ ] 報道記事の本文を使っていない（事実の確認にのみ用いた）
- [ ] **画像は上記3-1の1〜5のいずれかに該当する**（他社サイト・SNSからの取得がない）
- [ ] 提供画像の場合、**利用許諾の記録がある**
- [ ] 実在個人が特定される場合、**本人または公式発表に基づいている**
- [ ] 未成年が特定される内容になっていない
- [ ] 誰かを貶める・誰かの不幸を消費する構図になっていない
- [ ] 見出しが煽っていない（「涙腺崩壊」等を使っていない）
- [ ] 読者に教訓を垂れていない
- [ ] 政治的・宗教的対立を含んでいない

**1つでも「いいえ」が残る記事は、どれだけ良い話でも公開しない。**
