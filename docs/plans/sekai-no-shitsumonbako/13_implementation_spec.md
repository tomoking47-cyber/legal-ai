## 0. 最優先の2件（これだけは連載開始前に必ず）

| # | 項目 | 理由 |
|---|---|---|
| **1** | **URL設計の確定** | 後から変えると計測が分断され、**8週分のデータが比較不能になります**。リダイレクトも発生します |
| **2** | **`robots.txt` の確認** | AI検索クローラーを塞いでいたら、**そもそも引用されようがなく、企画が成立しません** |

**この2件が終わるまで、記事の公開を開始しないでください。**

## 1. URL設計

### 確定仕様

| 連載 | URL構造 | 例 |
|---|---|---|
| 世界の質問箱 | `/questions/<スラッグ>` | `/questions/toner-layering` |
| 世界のいいニュース | `/goodnews/<スラッグ>` | `/goodnews/ozone-layer-recovery` |
| 世界にひらく郷土レシピ | `/recipes/<スラッグ>` | `/recipes/nagano-oyaki` |

### 多言語（レシピのみ第1フェーズ対象）

```
日本語: https://（VVドメイン）/recipes/nagano-oyaki
英語　: https://（VVドメイン）/en/recipes/nagano-oyaki
```

- **言語ごとに独立したURLを持たせること。** 同一URL内でのJavaScript切替のみにしない（検索エンジン・AIが別ページとして認識できなくなります）。
- 言語コードは**パスの先頭**（`/en/...`）。パラメータ（`?lang=en`）にしない。

### スラッグの規則

- **英小文字・数字・ハイフンのみ。** 日本語・アンダースコア・大文字は使わない。
- 内容がわかる英単語で。連番だけ（`/questions/001`）にしない。
- **一度公開したスラッグは変更しない。**

### インデックスページ（各連載に1枚ずつ）

| URL | 内容 |
|---|---|
| `/questions/` | 質問箱の記事一覧（新着順＋カテゴリー絞り込み） |
| `/goodnews/` | いいニュースの記事一覧 |
| `/recipes/` | 郷土レシピの記事一覧（**地域別の絞り込みを付ける**） |

## 2. `robots.txt` の確認と設定

### やること

1. `https://（VVドメイン）/robots.txt` を開く。
2. **AI検索・AIアシスタント系のクローラーを `Disallow` していないか確認する。**
3. 塞いでいた場合、**情報戦略室に報告のうえ、方針を決めてから解除**すること（勝手に開けない・勝手に閉めない）。

### 判断の指針

| クローラーの種類 | 方針 |
|---|---|
| **AI検索の回答に引用するために巡回するもの** | **許可する**（許可しないと引用されない＝企画の目的が達成できない） |
| **AIの学習データ収集のみが目的のもの** | 経営判断事項。**情報戦略室の指示を待つ** |
| 通常の検索エンジンのクローラー | 当然許可 |

> クローラー名は各社が随時変更・追加します。**実装時点の最新の公式ドキュメントを確認**してください。
> 記憶や過去の設定ファイルのコピーで済ませないこと。

### 併せて確認

- [ ] 3連載のURLが `sitemap.xml` に含まれている
- [ ] `noindex` が誤って付いていない
- [ ] Google Search Console と Bing ウェブマスターツールの両方にサイトが登録・認証済み

## 3. 構造化データ

### 3-1. 世界の質問箱 → `FAQPage`

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [{
    "@type": "Question",
    "name": "＜質問文をそのまま＞",
    "acceptedAnswer": {
      "@type": "Answer",
      "text": "＜結論の1〜2文をそのまま＞"
    }
  }]
}
```

> **期待値の共有**：Googleは2023年8月にFAQのリッチリザルト表示を大幅に縮小しています。
> **検索結果の見た目が変わることは基本的に期待できません。**
> それでも実装するのは、質問と答えの対応関係を機械可読な形で明示するためです。
> 「見た目が変わらないから意味がない」という判断はしないでください。

### 3-2. 世界のいいニュース → `NewsArticle`

必須プロパティ：`headline` / `datePublished` / `dateModified` / `author`（VV編集部）/ `publisher` / `image`（**自社素材のみ**）

### 3-3. 世界にひらく郷土レシピ → `Recipe`【最重要】

**3連載のなかで、構造化データが最も効くのがここです。必ず実装してください。**

```json
{
  "@context": "https://schema.org",
  "@type": "Recipe",
  "name": "＜料理名＞",
  "image": ["＜自社撮影画像のURL＞"],
  "author": {"@type": "Organization", "name": "VALUE VILLAGE"},
  "datePublished": "YYYY-MM-DD",
  "description": "＜リード文＞",
  "recipeCuisine": "Japanese",
  "recipeCategory": "＜主菜/軽食 など＞",
  "prepTime": "PT20M",
  "cookTime": "PT25M",
  "totalTime": "PT45M",
  "recipeYield": "4 servings",
  "recipeIngredient": ["＜材料を1件1要素で＞"],
  "recipeInstructions": [
    {"@type": "HowToStep", "text": "＜手順1＞"}
  ],
  "inLanguage": "ja"
}
```

- 時間は **ISO 8601 duration**（`PT20M` ＝ 20分、`PT1H30M` ＝ 1時間30分）。
- `recipeIngredient` は**1材料＝1要素**。まとめて1行にしない。
- 英語版は `inLanguage: "en"` にし、**材料・手順も英語で**記述する。

### 共通：全記事に入れるもの

- `datePublished`（公開日）と `dateModified`（更新日）を**必ず明示**
- `author`：VALUE VILLAGE 編集部
- `publisher`：VALUE VILLAGE（ロゴを含む）

## 4. `hreflang`（レシピの多言語版）

日本語版・英語版の**両方のページに、両方への参照を入れる**（相互に指定しないと機能しません）。

```html
<link rel="alternate" hreflang="ja" href="https://（VVドメイン）/recipes/nagano-oyaki" />
<link rel="alternate" hreflang="en" href="https://（VVドメイン）/en/recipes/nagano-oyaki" />
<link rel="alternate" hreflang="x-default" href="https://（VVドメイン）/recipes/nagano-oyaki" />
```

- `x-default` は日本語版を指定。
- 対応する翻訳が存在しないページに `hreflang` を張らない。

## 6. 内部リンク（回遊とAIシグナルのため）

各記事の末尾に、以下を自動または手動で配置：

| リンク先 | 本数 |
|---|---|
| 同じ連載の関連記事 | 2〜3本 |
| **他の連載の関連記事** | **1本以上（必須）** |
| 連載インデックスページ | 1本 |

**なぜ他連載へのリンクを必須にするか**：
3連載を独立した3つの企画ではなく、**「VVはこの領域の情報源だ」という1つのまとまり**として認識させるためです。
回遊率が上がるだけでなく、AI・検索に対するシグナルとしても効きます。

## 7. 計測の実装

### 7-1. Search Console / Bing ウェブマスターツール

- 設定作業は不要（URLフィルタで集計するため）。
- **`/questions/` `/goodnews/` `/recipes/` でフィルタできることを、実装後に必ず動作確認**してください。
- Bing ウェブマスターツールの**AIパフォーマンス関連レポートの実仕様を確認し、情報戦略室に報告**すること（何が取れて何が取れないかが未確認のため）。

### 7-2. サーバーログ / CDNログでのAIクローラー集計【重要】

管理画面のレポートだけに依存しない、**自社で握れる指標**を作ります。

**実装内容：**

1. アクセスログから `User-Agent` を取得する。
2. AI検索・AIアシスタント系のクローラーによるアクセスを抽出する。
3. **URLパスごと**（`/questions/` `/goodnews/` `/recipes/` `/その他`）に、日次で件数を集計する。
4. 月次で情報戦略室にレポートできる形にする（CSV出力で十分。ダッシュボードは不要）。

**なぜ必要か**：プラットフォーム側のレポートは仕様変更が頻繁です。**管理画面が使えなくなっても計測が止まらない状態**を作っておきます。

### 7-3. GA4

- 3連載に**コンテンツグループ**を設定（`questions` / `goodnews` / `recipes`）。
- **シェアボタンのクリックをイベント計測**（いいニュース企画の主指標がシェア率のため、これは必須）。

## 8. 画像の取り扱い（システム側の担保）

| # | 要件 |
|---|---|
| 1 | 記事に使う画像は**自社素材ライブラリからのみ**選べるようにする |
| 2 | 外部URLの直接指定（ホットリンク）を**入稿フォームで禁止**する |
| 3 | 画像ごとに**出所と利用許諾の記録欄**を必須項目にする |
| 4 | `alt` テキストを必須項目にする（多言語版は言語ごとに） |

> **これはシステムで縛ってください。** 「編集部が気をつける」では、いつか事故ります。
> 3連載のなかで、法務事故が最も起きやすいのは画像です。
