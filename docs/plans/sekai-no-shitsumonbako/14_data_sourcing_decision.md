# 質問の源泉（データソース）に関する決定

- 起案：情報戦略室／2026-09-08
- 対象：3連載すべての「質問・ネタの取得方法」
- **決定事項：自動収集は「自社データ」に対して行う。他社サイトに対しては行わない。**

---

## 1. 検討した案と結論

会長CEOより「Redditの自動収集を実行し、内容を多少変更してVVバージョンにして掲載したい」という案が出た。
**結論：この案は採用できない。ただし、目的（スピードと量の確保）は別の手段で達成できる。**

| 案 | 判定 | 理由 |
|---|---|---|
| **A. 他社サイトを自動収集し、内容を多少変更して掲載** | ❌ **不採用** | 翻案権侵害。下記2章 |
| **B. 自社データを自動収集・分析して質問を抽出** | ✅ **採用** | 完全に自社の権利。今日から実装可能。下記4章 |
| C. 公式APIを規約の範囲内で使い、傾向データのみ取得 | ⏸ 保留 | 規約の精査と法務確認が前提。下記5章 |
| D. データ提供元と正式なライセンス契約を結ぶ | ⏸ 保留 | 完全にクリーンだが費用が発生。規模が出てから検討 |

---

## 2. なぜA案が採用できないのか

### 「多少変更する」は、著作権法上の免罪符にならない

これが最も重要な点である。

- 著作権法は、**複製**（そのまま使う）だけでなく、**翻案**（元の表現の本質的な特徴を残したまま作り変える）も権利者の許諾なしにはできないと定めている。
- したがって、**「少し書き換えたから大丈夫」は成立しない。** むしろ「元があることを認識したうえで書き換えた」ことになり、依拠性（元を見て作ったこと）が明白になる。
- **翻案は、丸写しより悪質と評価されることすらある。**

### 加えて、3つの実務上のリスクがある

| リスク | 内容 |
|---|---|
| **規約違反** | 主要プラットフォームは自動収集を規約で禁止し、データを有償ライセンスとして販売している。無断収集は相手のビジネスを直接侵害する行為と評価される |
| **提訴の実績がある** | Reddit社は2024年にGoogle社・OpenAI社とデータライセンス契約を締結し、2025年6月には無断収集を理由にAnthropic社を提訴している。**「たぶん大丈夫」が通用する相手ではない** |
| **検出されやすい** | AI検索の時代、元テキストとの類似は機械的に照合されうる。**人手で見つからないから安全、という時代ではない** |

### 経営判断としての結論

当社はナスダック上場企業である。

> **勝てる訴訟であっても、提起されること自体がコストになる。**
> 開示対応、レピュテーション、取引先からの照会、監査対応。
> **この企画の期待利益は、そのコストを上回らない。**

したがって、**A案は事業として割に合わない。** 法務判断以前に、経営判断として不採用とする。

---

## 3. しかし「自動化したい」という要求は正当である

会長CEOのご指示の本質は、「編集部員が手で読むのでは、スピードと量が出ない」という点にある。**これはまったく正当な問題意識である。**

したがって、**自動化を諦めるのではなく、自動化してよい対象に切り替える。**

---

## 4. 【採用】B案 — 自社データを源泉にする

### 実は、質問の源泉はすでに社内にある

| データ | 内容 | 権利 |
|---|---|---|
| **Search Console の検索クエリ** | **実際にVVへたどり着いた人が打った検索語。質問形式のクエリがそのまま取れる** | **完全に自社のデータ** |
| **サイト内検索ログ** | VVサイトに来た人が、サイト内で何を探したか | **完全に自社のデータ** |
| **カスタマーサポートの問い合わせ** | 顧客が実際に困っていること | **完全に自社のデータ** |
| **商品レビュー・お客様の声** | 購入者が疑問に思ったこと | 自社データ（※会員規約の確認は必要） |
| **SNSでVV宛に届いた質問** | 直接寄せられた疑問 | 自社データ（※本人が特定されない形に加工） |

### この案が優れている理由

1. **法務リスクがゼロ。** 自社のログである。誰の許諾も要らない。
2. **精度が圧倒的に高い。** 海外の誰かの疑問ではなく、**実際にVVに来た人の疑問**である。書けば必ず読者がいる。
3. **自動化できる。** 今日から実装できる。
4. **第2フェーズと地続き。** 会員コミュニティへの移行が、切り替えではなく延長になる。
5. **他社が真似できない。** 自社データは競合が持っていない。**これがそのまま参入障壁になる。**

### 実装内容（情報戦略室 → CODE）

```
① Search Console API から検索クエリを定期取得（日次または週次）
② 疑問形のクエリを自動抽出
   （「とは」「なぜ」「どっち」「方法」「違い」「いつ」「何」等を含むもの）
③ 表示回数はあるが順位が低い＝「需要はあるが answers がない」クエリを優先度上位に
④ サイト内検索ログ・CS問い合わせログを同じ形式に正規化してマージ
⑤ 出現頻度順にランキングして、週次で編集部にCSVで渡す
```

### 実装状況：**完成済み**

| 項目 | 状態 |
|---|---|
| 実装場所 | **`tools/question_miner/`**（リポジトリ直下） |
| 手順書 | `tools/question_miner/README.md`（**非エンジニア向けに全4ステップで記載**） |
| 動作確認 | `python question_miner.py --demo` で**認証なしで即確認可能** |
| 出力 | 優先度順のCSV（Excelで開ける）＋ 上位30件のMarkdownレポート |

**③の「表示はあるが順位が低いクエリ」が最も価値が高い。**
読者が求めているのに、VVがまだ十分に答えられていない質問である。**そこを埋めれば、必ず数字になる。**

### 海外の話題も扱いたい場合

**編集部員が人の目で読む観察は、これまでどおり継続する。** 自動化しないだけであり、禁止ではない。
自社データで質問の「核」を決め、海外の議論は**その質問が世界共通であることの確認**に使う。

---

## 5. 【保留】C案 — 公式APIを規約の範囲内で使う

将来的な選択肢として残す。ただし**以下が未確認のため、法務確認前に着手しない。**

- 各プラットフォームのAPI利用規約における、**商用利用の可否と条件**
- 取得データの**保存・再利用に関する制限**
- レート制限、登録要件、料金体系

**未確認事項をここに正直に記録しておく：現時点の各社API規約の詳細を、当室は把握していない。**
着手する場合は、必ず①最新の公式規約の精査 ②法務レビュー ③必要なら先方への照会 を経ること。

なお、仮にAPIを使う場合でも、**取得するのは「話題の傾向・頻度」までとし、投稿本文を保存・再利用しない**という原則は変えない。

## 6. 誤解を防ぐための整理

| よくある誤解 | 正しい理解 |
|---|---|
| 「少し変えれば自分の著作物になる」 | ❌ **翻案権侵害。変えても元の表現の特徴が残れば侵害** |
| 「無料で見られるなら自由に使える」 | ❌ 無料公開と著作権放棄は別 |
| 「出典を書けば転載してよい」 | ❌ 出所明示は引用の要件のひとつにすぎない |
| 「みんなやっている」 | ❌ 上場企業の判断基準にはならない |
| 「自動収集も、読むのと同じ行為だ」 | ❌ 規約上まったく別に扱われる |
| **「情報を見に行くこと自体がダメ」** | ❌ **これも誤解。見る・読む・理解するのは完全に自由**（`12_faq_copyright.md`） |

---

## 7. 決定

1. **他社サイトへの自動収集は行わない。** 内容を変更して掲載することも行わない。
2. **自動収集は自社データに対して実施する。** 情報戦略室が仕様を策定し、CODEが実装する。
3. 海外コミュニティの観察は、**人の目による閲覧として継続**する。
4. 公式API・データライセンスは、法務確認を経たうえで将来の選択肢として保留する。

**この決定は、企画のスピードを落とすためのものではない。**
**むしろ、自社データという、より精度が高く、誰にも止められない源泉に切り替えるための決定である。**
