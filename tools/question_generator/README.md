# 質問候補ジェネレーター（question_generator）

カテゴリーごとに質問候補を大量生成するツール。

```
python generate.py            各カテゴリー500件（合計2,500件）
python generate.py --n 1000   各カテゴリー1000件
```

出力：`output/questions_<カテゴリー>.csv` ＋ 全件まとめの `questions_all.csv`

## 出るもの・出ないもの

| | |
|---|---|
| **出るもの** | **質問候補**。話題リスト × 質問フレームの総当たり |
| **出ないもの** | 記事。そのまま公開できる質問文。需要データ |

**機械的な組み合わせなので、日本語として不自然なものが混ざります。**
たとえば「洗顔の回数は毎日やったほうがいいの？」のように、話題とフレームが噛み合わない行が出ます。
**編集部が選び、自然な日本語に書き直すことを前提にしてください。**

## 件数を増やすには

`topics.py` の話題リストに語を足すだけです。フレーム数は変えなくて構いません。

- 話題を10語足すと、日本語カテゴリーは150件、英語カテゴリーは120件増えます。
- 現在の上限（概算）：beauty 約880／fashion 約600／health 1,215／trend 1,185／inbound 912／wisdom 912

## CSVの列

| 列 | 意味 |
|---|---|
| 質問候補 | 生成された質問文（**要リライト**） |
| 話題 | 元になった話題 |
| 棚 | beauty / fashion / health / trend / inbound / wisdom |
| **法務チェック** | **「必須」なら薬機法等のレビューへ** |
| 要注意 | 制度・安全に関わる話題 |
| 状態 | 既定は「未確認」 |
| 3ソース確認日 / 担当 | 編集部が記入する欄 |

## 使う手順

1. CSVをExcelで開く
2. 棚が偏らないように、上から順ではなく**分散して選ぶ**
3. 選んだ質問を**3ソース原則**で確認（`03_editorial_workflow.md`）
4. 自然な日本語・英語に書き直す
5. 執筆 → `05_article_template.md` / `17_standard_disclaimers.md`
6. 公開前に `tools/translation_checker/` を通す

**この順番を飛ばすと、企画のガードが効きません。**

## 優先順位づけ（rank.py）

```
python rank.py            上位100件
python rank.py --n 200    上位200件
```

出力：`output/priority_top100.csv`（**編集部に渡すのはこれ**）

選定の考え方：

| 観点 | 内容 |
|---|---|
| フレームの質 | 記事にしたとき中身が出る問い方を高く評価（「よくある誤解は」「なぜ起こるの」等） |
| 話題の需要 | 検索・AI検索で繰り返し問われる話題を高く評価 |
| 法務リスク | 薬機法等のレビューが要るものは**後ろへ**（除外はしない） |
| **棚のバランス** | **5カテゴリーから均等に取る**（KPIの棚別比較を成立させるため） |
| **言い回しの多様性** | **同じフレームばかりが上位を占めないよう上限をかける** |

## 質問の日本語が不自然にならないようにしている仕組み

話題を3種類に分け、種類に合うフレームだけを当てています。

| 種類 | 例 | 当てるフレーム |
|---|---|---|
| `act` 行為・手順 | 昼寝、作り置き、二重洗顔 | 「毎日やったほうが」「やりすぎると」「いつやるのが」 |
| `obj` モノ | 化粧水、枕、フライパン | 「選ぶときは何を見れば」「正しい使い方は」「どう保管すれば」 |
| `state` 状態・現象 | 肩こり、むくみ、毛玉 | 「なぜ起こるの」「気になるときは」「放っておいても大丈夫？」 |

これをしないと「昼寝の正しい順番は？」のような、意味の通らない質問が大量に出ます。
**それでも組み合わせによっては不自然な行が残ります。編集部が書き直す前提です。**
